# Job Tracker — Product Spec

## Purpose
A local, single-user web app to organize job applications for **Project Manager** and **Developer** roles: track every application, keep CV/personal info ready to copy into forms, keep links to job platforms handy, manage follow-up ToDos, and see overall progress on a Dashboard.

## Scope (v1)
- Local only. Runs on `localhost` via `npm run dev`. No auth, no multi-user, no cloud sync.
- Single owner (you). All data lives in a local SQLite file (`job-tracker/data/app.db`), plus uploaded PDFs in `job-tracker/data/uploads/`.

## Tech stack
- **Next.js (App Router) + TypeScript**
- **Prisma** ORM with **SQLite** provider
- **Tailwind CSS** for styling
- Server Actions / Route Handlers for CRUD (no separate backend)
- **Local LaTeX toolchain** (e.g. MacTeX or BasicTeX) providing `pdflatex`/`xelatex` on `PATH` — required only for the in-app "compile CV to PDF" feature; the rest of the app has no dependency on it.

## Data model

### Application
The core entity — one job you applied (or plan to apply) to.
| Field | Type | Notes |
|---|---|---|
| id | string (cuid) | |
| company | string | required |
| roleTitle | string | required, e.g. "Senior Project Manager" |
| roleType | enum: `PM`, `DEV` | required — the two role families you're tracking |
| platformId | FK → Platform | optional, which board/site it came from |
| jobPostingUrl | string | link to the original posting |
| status | enum: `WISHLIST`, `APPLIED`, `PHONE_SCREEN`, `INTERVIEW`, `TECHNICAL_TEST`, `OFFER`, `REJECTED`, `WITHDRAWN` | drives the pipeline/funnel |
| appliedDate | date | nullable (null while still `WISHLIST`) |
| location | string | e.g. "Remote", "Paris, FR" |
| salaryRange | string | optional, free text |
| contactName / contactEmail | string | optional recruiter info |
| cvVersionId | FK → CvVersion | optional — which CV was sent |
| notes | text (markdown) | freeform |
| createdAt / updatedAt | datetime | |

### StatusChange (history)
Tracks the funnel over time for the dashboard and per-application timeline.
| Field | Type |
|---|---|
| id | string |
| applicationId | FK → Application |
| status | enum (same as above) |
| changedAt | datetime |
| note | string, optional |

### CvProfile (singleton)
Your structured personal info, kept ready to copy into any application form.
| Field | Type |
|---|---|
| fullName, email, phone | string |
| address, linkedinUrl, portfolioUrl | string, optional |
| summary | text — short professional pitch |
| skills | string[] (tags) |
| experience | JSON list: `{title, company, startDate, endDate, bullets[]}` |
| education | JSON list: `{school, degree, startDate, endDate}` |
| languages | string[] |

Every field/section has a **"Copy" button** in the UI for one-click paste into external forms.

### CvVersion
You may tailor your CV PDF differently for PM vs Dev roles.
| Field | Type | Notes |
|---|---|---|
| id | string | |
| label | string | e.g. "PM-focused v2", "Dev — backend" |
| filePath | stored PDF | optional — from a manual upload, or generated by compiling `latexSource` |
| latexSource | text | optional — LaTeX source for this version, edited in-app |
| compiledAt | datetime | optional — when `filePath` was last generated from `latexSource`; used to flag a stale PDF after further edits |
| compileError | text | optional — last compiler error output, shown in the editor if the most recent compile failed |
| notes | string | optional |
| createdAt / updatedAt | datetime | |

A version can have `filePath` only (plain upload, today's flow), `latexSource` only (drafted but never compiled), or both. Editing `latexSource` after a successful compile does not touch `filePath` until the next compile — the UI flags the PDF as stale (`updatedAt` on the version newer than `compiledAt`) rather than silently regenerating it.

### Platform

| Field | Type |
|---|---|

| name | e.g. "LinkedIn", "Welcome to the Jungle", "Indeed" |
| url | homepage/login link |
| username | optional (never store passwords) |
| notes | optional |

Tasks, optionally linked to a specific application.
| Field | Type |
|---|---|
| id | string |
| title | required |
| description | optional |
| dueDate | date, optional |
| done | boolean |
| priority | enum: `LOW`, `MEDIUM`, `HIGH` |
| applicationId | FK → Application, optional |
| createdAt | datetime |

## Screens

1. **Dashboard** (`/`) — funnel chart by status, split by roleType (PM vs Dev), response rate, upcoming/overdue ToDos, applications with no activity in 7+ days (follow-up nudge), recent activity feed.
2. **Applications** (`/applications`) — filterable/sortable table (status, roleType, platform, date), search by company/role.
3. **Application detail** (`/applications/[id]`) — full edit form, status dropdown (writes a StatusChange), notes, linked ToDos, quick-copy of CV fields.
4. **New application** (`/applications/new`) — quick-add form.
5. **My CV / Info** (`/cv`) — structured fields with per-field/section copy buttons, PDF upload + list of CV versions with download. Each CV version can also be edited as LaTeX source in an in-app code editor (syntax highlighting, monospace), with a "Compile to PDF" action that runs the local `pdflatex`/`xelatex` toolchain and refreshes the downloadable PDF; compile failures show the compiler's error output inline instead of updating the PDF, and a version whose source changed since the last successful compile is flagged as stale.
6. **Platforms** (`/platforms`) — manage the list of job boards/links.
7. **ToDos** (`/todos`) — full task list, filters (overdue/done/all), create standalone or linked to an application.

## Explicit non-goals (v1)
- No login/auth (single local user)
- No email/calendar integration
- No hosting/deployment
- No password storage of any kind
